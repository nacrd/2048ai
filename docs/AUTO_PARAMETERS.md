# 自动参数

刷新页面后，普通 AI 默认选择「参数控制：自动」。保留所选算法，在「自动偏好」中选择速度优先、均衡或稳健，并设置单步软时间上限。默认均衡、上限1000ms；上限不是每步固定等待时间。手动字段暂时禁用，但其值保留，切回手动后恢复。exact 和 TAS 显示并使用手动参数，有限 H 的含义不变；返回普通算法时恢复先前参数控制偏好。普通/TAS的手动时间档位分别保留。

## 每步如何调整

1. 复用 CPU Worker，只传棋盘与求解选项。枚举一步出块，计算空位、邻接指数差、大块阶段、合法方向数、启发式候选差距与出块即死风险；不读取真实 RNG。
2. 按当前局面分为宽松、复杂、危险。新危险立即加预算，局面转宽松后预算缓慢下降，减少连续两步参数剧烈跳动。
3. 搜索模式调整深度上限与节点预算；Rollout 联合调整窗口长度和每方向样本请求数。近期无成功样本优先延长窗口；如果 `目标 > 当前质量 + 4×H`，本窗口不可能达标，减少无效采样。这个条件不证明无限步不可达。
4. 每次成功返回后按算法、目标类型、棋盘尺寸与实际 CPU/CUDA 后端更新访问量/耗时的平滑估计。候选接近或触及预算会提高后续计算倾向，实际完成深度帮助避免持续请求过深的层。这个反馈影响后续局面，每步仍重新探测当前棋盘。

速度优先降低时间、窗口和采样倾向；稳健提高困难局预算与采样下限。初始吞吐估计属于保守设定，运行后按实测修正；启动/排队明显超时的样本不用于更新吞吐。默认参数尚未经过整局胜率调参，不能据此承诺提高多少胜率。

| 项目 | 自动策略范围 | 手动设置 |
| --- | --- | --- |
| 时间 | 按局面约30ms起，上限由用户选择，最高5000ms | 原预算档位 |
| 搜索深度 | 通常2–12，只有一个合法方向时1；实际完成层受预算约束 | 原正安全整数范围 |
| Rollout窗口 | 8–512步，按吞吐、风险和目标调整 | 没有64步或512步业务上限 |
| 每方向请求样本 | 通常16起，稳健32起，最高65536；实际可能少于请求数 | 1–65536 |
| 搜索节点 | 2000–4000000，与近期访问速度和可用时间联动 | 原正安全整数范围 |

样本数通常向下取2的幂；稳健档保留最低采样量。最低工作量、首次查表/Worker启动、一个已经发出的批次、CUDA初始化/排队，以及失败后CPU回退都可能超过软上限。探测耗时从本步预算中扣除，剩余不足时仍允许最小计算以提供合法动作。时间栏显示总请求耗时，自动面板列出计划与实际深度/样本，供使用者判断延迟与质量。

Rollout 自动后端使用已有设备校准条件：CUDA候选满足尺寸/窗口/批量阈值才采用GPU吞吐估计并路由至CUDA，否则用CPU估计和CPU执行。显式选择CUDA时仍尝试CUDA；自动参数下失败会扣除已用时间、重新用CPU吞吐规划窗口/采样，保留原本单步总预算，耗尽时仅做最小计算。自动请求的HTTP看门狗使用剩余预算加100ms通信余量。CPU与CUDA的反馈分别记录，回退只用实际CPU计算时间更新CPU速度；强力与Expectimax继续用CPU。自动模式不会修改手动后端选择或自动下载模型。

目标模式勾选继续游玩时，根最大块达到目标后，将普通近似AI的内部目标推进到下一倍最大块；存档和棋盘目标保持原值。到2³⁰上限后转为提高得分，分析标题按本次实际目标类型显示。Rollout仍报告所显示目标与所显示H内、固定后续策略的模拟概率；自动调参不会把启发式值改称胜率。

探测与求解均受既有请求版本保护；暂停/编辑/参数变更会拒绝旧结果，旧结果不会更新调参反馈。重新加载、编辑、手动接管、撤销、恢复TAS起点或修改决策参数会清空反馈；暂停保留本机速度估计。反馈仅存在当前页面内，不写进游戏存档。

本轮仅完成构建与静态核验，未运行测试、游戏、胜率或CPU/GPU性能评测。现有 `bench:ab` 继续使用显式固定参数，不自动应用页面调参，以保留旧对照定义；新自动策略的实际收益需另行验收。
