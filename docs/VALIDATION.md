# 实施记录

环境：Windows，Node.js 26.3.1，Python 3.13.15，GTX 1660 SUPER（6 GiB），驱动 617.14；隔离环境使用 CuPy 14.2.0 的 CUDA 12 wheel 运行库。上游基准固定为 `478b6ec346e3787f589e4af751378d06ded4cbbc`。

## TAS 新增前

构建通过，Vitest 17 项通过，包含 8000 次上游移动对照、精确枚举、存档和 RNG 复现。Python 3 项通过，包含实际 GPU 的 240 次共享移动、1920 条得分轨迹、1920 条目标轨迹及 2560 次额外移动检查。界面已核验游玩、暂停、撤销、回放、编辑、JSON 下载与恢复、搜索取消、服务离线回退和响应式布局。

质量基线：100 个独立种子，Expectimax 固定 10000 节点 / 深度 3，均到终局。平均分 39185.96，中位分 36340；2048 达标 79/100（95% Wilson 约 70.0%–85.8%），4096 达标 26/100（18.4%–35.4%），8192 达标 0/100（上限约 3.7%）。求解 P50 5.10 ms、P95 6.87 ms。原始数据见 [CPU 报告](../benchmarks/cpu-results.json)，配置与界面默认不同。

GPU 同策略评测：4×4 中盘、32 步、5 次重复，对比 Numba 并行 CPU 与 CUDA，含 HTTP、拷贝及统计。每方向 512 条轨迹时 CPU/CUDA P50 16.09/4.31 ms（约 3.73 倍）；2048 条为 56.19/4.93 ms（约 11.39 倍）；8192 条为 205.68/16.53 ms（约 12.44 倍）。小批量可能更慢。见 [GPU 报告](../benchmarks/gpu-results.json)。自动选择限匹配设备且 4×4、H≥32、每方向≥512 条。

## TAS 新增后

新增固定种子 / 理想出块规划、路线工作台、预览、逐帧执行、起点恢复、路线导入导出。已完成 TypeScript 编译、生产构建和独立静态核验，覆盖最优性标签、预算中断、取消版本隔离、导入复算；修复非法目标输入后遗留预览画面的状态问题。

按使用者要求，新增 TAS 的游玩与运行测试由使用者完成，未重跑测试套件或 benchmark。旧验证结果不作为 TAS 运行验收结果。

后续移除前端、TAS 与 API 的 64 步上限，CUDA 步数升级为 64 位，CPU 与 TAS 深度搜索改为显式栈；仅做编译检查，不重跑上述验收数据。

## 续玩优化

加入五位指数的4×4行查表、多方向阶段评分、rollout同概率辅助评分、Worker复用、GPU缓冲区复用、可配置节点预算、TAS beam/hybrid与保守下界剪枝。新增离线分段续玩脚本，存档与输出路径冲突时拒绝，检查点保存原RNG和实际动作/出块路线。

已进行编译及两份独立静态核验，修复输出覆盖输入的冲突情况和下界文案可能出现负步数的问题。没有重跑测试套件或质量/性能benchmark。旧报告和GPU自动阈值尚未按新策略重新测量；随后对使用者指定存档的续玩属于实际目标工作，不计作新版胜率基准。

增加固定 RNG 的质量障碍证明及离线有效目标调整。证明只依赖质量守恒、合法出块数值前缀和二次幂表示的最少格数；不将束搜索失败当成不可达。实际目标路线会逐步通过通用移动引擎及出块校验复算后单独保存。

## 底层推理优化

浏览器Rollout增加最多4路Worker池，按连续轨迹编号分片、按编号聚合并整体取消。Numba移动改为轨迹私有scratch和棋盘双缓冲，避免每步/每条线分配；保留列优先出块及种子派生。CUDA增加全部尺寸的模板专门化和较小空位数组，去除终步/已达标后的冗余贪心。TAS节点缓存最大块与达标状态；评分辅助计算复用局部棋盘。

服务采用分后端锁与专用调度线程、自适应批次，取消后等待原生计算完成再释放锁。CUDA安全整数结果在设备归约；大质量/长步数回退旧汇总。GPU初始化仅编译，不自动运行验证轨迹。按使用者要求，本轮仅做构建、Python语法、Numba/CUDA编译及静态核验，不运行测试套件、游玩验收或benchmark；旧吞吐数据不代表新版。

本机仅编译资源对照：旧通用CUDA内核每线程62个寄存器、224字节局部存储；新版4×4为61个寄存器、64字节局部存储。评分路径使用1440字节常量索引表并抑制蛇形/方向循环过度展开。五种尺寸全部NVRTC编译成功，Numba移动/辅助评分/并行rollout签名编译成功。资源减少不是实际加速比，仍需使用者测量。
